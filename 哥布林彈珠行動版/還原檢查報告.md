# Peglin 瀏覽器移植：第一階段還原檢查

檢查日期：2026-10-14。目標是純遊戲、保留原版內容，研究手機／平板瀏覽器獨立執行的可能性。

## 結論

**已還原出 Unity 專案結構，兩組核心 C# 原始碼能重新編譯；有繼續移植的基礎。尚未完成 Unity Editor 匯入、WebGL 建置或瀏覽器遊玩測試。**

這是從本機 Windows 成品還原的專案，不是開發商提供的完整原始專案。資料與邏輯可恢復，不代表原始 Shader、完整編輯器套件、所有欄位或執行行為已恢復。

使用者選擇「沒有 Unity 帳號，先完成還原檢查」，因此本階段不安裝 Unity Editor，不進行需要授權的建置。

## 已發現的移植工作

1. **Shader／畫面尚未恢復。** 85 個 Shader 是 DummyShaderTextExporter 產生的佔位內容。這些不具備原版渲染功能；要恢復套件標準 Shader，並另外處理原版自訂效果。不能用此輸出承諾「畫面一模一樣」。
2. **Unity 套件與 Editor 匯入仍需修復。** package manifest 只有引擎模組，URP、Addressables、TextMeshPro 等是匯出的 Player DLL。75 份 DLL 的 metadata 在 Editor 平台停用；需要在工作副本修正套件與 PluginImporter 設定，再用 Editor 確認。不能僅把 DLL 通通啟用，否則可能和重新安裝的套件撞名。
3. **場景／資源載入仍是 Windows Addressables。** EditorBuildSettings 只有 PreMainMenu；其他場景透過 PeglinSceneLoader 的 Addressables.LoadSceneAsync 載入。保存的 catalog 包含 13 個 StandaloneWindows64 bundle 路徑，要從還原素材重建 Addressables 清單與 WebGL bundles，不能直接使用 Windows bundle。
4. **Steam／平台服務需做瀏覽器適配。** SteamManager 呼叫 SteamAPI 原生函式；Rewired 保留 Windows 版本 DLL，需檢查 WebGL 輸入路徑。原版也含 WebGL 平台判斷與觸控切換，但這只表示程式有相關分支，並不證明有完整可用的官方 Web 版本。
5. **購買服務與存檔必須另行處理。** IAPManager 對 WebGL 也啟動購買服務；現有設定屬原開發商，不是這個測試專案的服務。這輪沒有修改購買／授權檢查。存檔 File I/O 要驗證瀏覽器持久儲存、重開網頁與更新版本後能否保留。
6. **少量缺件。** 日文字型圖集、俄文字型圖集有匯出警告；AnimationImporterConfig 缺 Editor 腳本，MM_6D_Shake 的 m_Script 為 0。缺件清單見 unresolved-references.json，不代表所有未解析項目都會在每次遊玩出現。

GUID 檢查只確認檔案存在；外部引用的 fileID、實際型別／欄位反序列化、Shader 結果仍要由 Unity Editor 驗證。本地 fileID 掃描是靜態候選缺口，不直接等同執行錯誤。

## 下一階段的順序

1. 自行建立 Unity 帳號，在 Unity Hub 啟用適用的授權，安裝 Unity 2022.3.62f2 和 WebGL Build Support。先以同版 Editor 做還原驗證，避免同時引入引擎升級的變數。
2. 保留本次還原原樣，建立工作副本，修復套件、PluginImporter、Shader 與缺件，確認 Editor 匯入結果。
3. 重建 Addressables，先測主選單→地圖→戰鬥場景的完整載入流程，再處理瀏覽器平台服務。
4. 輸出本機 WebGL，實測瞄準、發射、碰撞、傷害、敵人回合、結算與存檔；桌面瀏覽器通過後，再測 iPhone／iPad Safari 與 Android Chrome 的觸控、效能、記憶體和重新開啟。
5. 確認可玩的 Web build 與適當發布權限後，再評估網站部署。此階段沒有可部署的遊戲網站。
